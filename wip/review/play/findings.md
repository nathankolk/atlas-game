## Findings

### F1 (minor) Returning player: Stats and Home headline say "Rounds played — none yet" / "Time played — none yet" while records hold dozens of rounds
- Where: Stats headline figures (`renderStats`, KPIs from `mastery.totals()`), Home masthead.
- Evidence: oldplayer.js seeds only the OLD stores (atlas-records with gamesPlayed 4+2+3+1+9+31+6+2+2+5+2+7, daily attempts for 6 days). Stats then prints "ROUNDS PLAYED — none yet", "TIME PLAYED — none yet", "DAY STREAK — starts with a round", and further down the same page "Personal records ... Europe ... ROUNDS 9", "31 puzzles played in all", Daily "CURRENT STREAK 6 days" (old-stats.txt). After one new round the headline reads 1 round for good. Nothing is lost in storage; the headline figure is wrong for every player who had the old app.
- Fix idea: when counting rounds, add the gamesPlayed of atlas-records entries last played before mastery's first day (or a one-time note of the pre-mastery total), or label the figure "since <first mastery day>".

### F2 (major) A round whose push failed (offline, 413, 5xx) is not pushed when the app is next opened, and the sync status then says "Up to date"
- Where: `syncPull()` index.html ~15773 sets `lastError: null` on every successful pull; `syncOnAppLoad()` ~15790 pushes only when the pull was `stale`; `syncAfterGameEnd()` is the only other push.
- Repro (sync2.js step 2, sync2.log): device B linked; go offline; finish Flags of Oceania -> nav dot error, meta lastError "network" (right). Go online, reopen the app: Settings says "Up to date · last synced just now", dot is green, but the server blob has no `flag|Oceania|normal` and device A never receives the round. It stays unmirrored until B finishes another round or presses Sync now.
- Same root for 413 (step 3): after a 413 the Settings line reads "Your progress has grown too large to sync…"; reopen the app (pushes still 413) and it reads "Up to date · last synced just now" with no error dot.
- Also by the same design (code, and sync.js S3 where B's push replaced the blob A had just written): a push sends this device's snapshot only, so the server holds whichever device pushed last; a device loaded before another device's push overwrites that push at its own round end, and the first device does not send again until it finishes another round. If that device is retired or cleared first, its rounds are on no other device.
- Fix: do not let a pull clear a push error; on load, after a successful pull, push when the last push failed or local progress changed since the last successful push (a dirty flag set by every store write).

### F3 (major) Progress made on a second device after a reset elsewhere, but before that device next loads, is erased (lost on every device and the server)
- Where: `syncApplyRemote()` ~15656: `remoteReset > localReset` -> `eraseProgress()` wipes every store, whatever its date.
- Repro (sync2.js step 4): A and B linked and in sync. A: Settings -> Reset progress (resetAt T pushed). B's tab is still open (no reload): B plays Name It Oceania to the end AFTER T; its push carries resetAt 0 and replaces the server blob. A reopens: blob set aside as stale, A pushes its empty state. B reopens: pull sees resetAt T > 0 -> B's stores all wiped, including the Name It round played after the reset. sync2.log: "4. B reopened: records {} mastery {days:{},items:{},v:2}"; A has nothing either.
- Fix: on a newer remote reset keep what is dated after it (records by lastPlayed/date, daily attempts by completedAt, pin games by at, focus/learn by savedAt, mastery items/day rows by day >= reset day), or pull before every push so a device learns of the reset before it plays on.

### F4 (minor) Synced totals take the larger device, not the sum, for a day both devices played
- Where: mastery `mergeStores` (day rows keep the larger of each number), `syncMergeRecordEntry` gamesPlayed = max (the latter is the known D14).
- Evidence (sync2.log step 1): A played 1 round (7 answers), B 2 rounds (20 answers) the same day, then synced: `mastery.totals()` on both = games 2, questions 20; Oceania record gamesPlayed 1 though it was played twice. Per item, the device with more answers wins, so A's seven answers on Oceania are not in the merged history. Stats' Rounds played / Activity / first-try accuracy under-count for a family sharing one code on the same day. progress.md calls `mastery.totals().games` "the reliable round count"; under sync it is not.

### F5 (major) Daily Five card does not roll over at UTC midnight while Home is open; its stale buttons then act on the NEW day
- Where: `startDailyCountdown()` index.html ~4732-4752: `next.setUTCHours(24,0,0,0); const ms = next - new Date(); if (ms <= 0) { renderToday(); return; }` — `next` is always the midnight after "now", so ms is never <= 0 and the redraw never happens (the old app had the same dead check at old L4158). `'replay-daily': () => startDailyReplay(todayUtcKey())` ~15270; `shareDailyResultFromMenu()` ~14736 reads `todayUtcKey()`.
- Repro (daily.js, Playwright clock): 23:40 UTC play today's five (#207), return Home: card "Today's puzzle complete · Next puzzle in 00:19:46". Let the clock pass midnight (00:10 UTC): card still reads "PUZZLE NO. 207 · Next puzzle in 23:49:41 · Today's puzzle complete", masthead still "Wednesday 18 November … Today's Daily Five is done". On that stale card: "Share Result" does nothing; "Practice Replay" starts Daily #208 — the new day's five countries (Canada, Comoros, Falkland Islands, France, Lebanon) as a practice round, before the real attempt; leaving it shows #208 as unplayed, so the scored attempt can then be played having seen the answers. (UTC midnight is 7 pm US Eastern.)
- Fix: remember the date key the card was drawn for; in tick(), if `todayUtcKey()` differs, call renderHome/renderToday. Make the played card's Replay and Share use the card's own date key, not today's.

### F8 (major) Name It: typing a country's full name is cut short at its accepted short form, and the rest of the typing lands in the next question
- Where: `onAnswerInput()` ~6889: an exact, non-partial match is taken at once; `startsAnother()` in Quiz.matcher only looks at OTHER entries, so an alias that begins the same country's full name ("bosnia", "trinidad", "antigua", "saint kitts"/"st kitts", "saint vincent"/"st vincent") or a name that begins its own alias ("United States" / "united states of america") is not treated as partial. After acceptance the field is locked for 900 ms, then the next question takes the keystrokes.
- Repro (spill.js, 5 keys a second, then Enter): "Bosnia and Herzegovina" -> accepted at "Bosnia"; when the typing ends the question on screen is Chad, the field holds " Herzegovina", Enter gives "That name isn't in this atlas — check the spelling" (shots/spill-Bosnia_and_Herzegovina.png). Same for Antigua and Barbuda (" Barbuda"), Saint Kitts and Nevis (" Nevis"), Saint Vincent and the Grenadines (" the Grenadines"), Trinidad and Tobago ("d Tobago"), United States of America ("merica" — one keystroke away from "america", an accepted name of the United States, which with Enter would be a wrong try on the next country).
- Fix: treat a spelling as partial when it is a proper prefix of another spelling of the SAME entry (wait for Enter or a short pause), or swallow keystrokes until the next question's field has been focused/cleared and ignore input typed within a moment of the question changing.
